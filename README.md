# 자율주행차 배터리 AI 공장

자율주행차에 들어가는 대용량 배터리(수십 Ah급 셀)를 다루는 연구실 해설 시리즈입니다. 공장마다 3D 모형이 있고, 같은 12칸 배치와 같은 캐릭터 자리(전신)를 씁니다. 연구실 스킬 ai-lab-explainer v1.14("낮의 연구실", 흰 배경)를 따릅니다.

## ③ 배터리 생산 공장 (`factory.html`)

셀을 만드는 완전 자동화 라인(믹싱 → 코팅 → 건조 → 압연 → 슬리팅 → 적층 → 조립·실링 → 전해액 주입 → 화성 → 에이징·검사·라벨)을 1시간 단위로 7일 돌립니다(`build/fsim.js`).

- **라벨**: 기계마다 잰 센서 값 18개가 셀 라벨에 기록됩니다. 라벨 CSV를 내려받아 ①·②의 학습 데이터로 이어 볼 수 있습니다.
- **증산 → 병목·불량**: 속도를 올리면 화성(최대 속도 1.05×)이 병목이 되어 앞에 재공품이 쌓이고, 불량률은 e^{2(속도−1)}배로 늡니다. 화성 설비를 늘리면 병목이 적층으로 옮겨 갑니다.
- **24시간 → 고열**: 쉬는 시간이 없으면 기계 온도가 오르고, 55 °C부터 불량이, 60 °C부터 센서 오기(치우침·멈춤·자리 바뀜)가 늡니다. 오기 라벨은 검사 유출도 늘립니다.
- **전기료**: 시간대 3단계 예시 요금(95·140·210원/kWh), 기본 부하 150 kW(드라이룸 등), 냉각·이중 검증 전력.
- **최적화**: 목표 함수 = 하루 이익(매출 − 재료 − 유출 − 전기 − 설비), 제약 = 라벨 오기율 3% 이하. 자동 최적화는 11,440가지 격자 탐색(상위 10개가 2% 안 — 평평한 꼭대기).
- **실습 키트**: 미션 K1 병목 찾기 · K2 병목 풀어 증산 · K3 24시간 열 관리 · K4 전기료 줄이기 · K5 종합 최적화(자동 최적값의 97%), 기록지 CSV, 교사용 메모.
- **대결**: 밤 16시간(초파리) vs 24시간·속도 1.1×·화성 +1(주판봇) → 냉각 1단이면 초파리(주판봇 라벨 오기율 14.8% 실격), 2단이면 주판봇 → **C 조건부**.
- 기본 설정(16시간 · 6시 시작 · 냉각 1단): 하루 양품 4,658셀, 불량률 2.95%, 라벨 오기율 2.48%, 하루 이익 약 797만 원. 자동 최적: 24시간 · 속도 1.0× · 냉각 2단, 하루 약 1,327만 원 (모두 설명용 예시값).

## ① 배터리 불량품 판정기 (`classifier.html`)


| 섹션 | 내용 |
|---|---|
| 엔진(모델) 조립 공장 3D 그림 | 12공정: P1~P4 데이터세트 → P5 머신러닝 도감관 · P6 신경망 도감관 → P7 엔진 장착 → P8 시운전 벤치 → P9 정비 ①~⑩ → P10 비교·선정 → P11 출고 → P12 2편 검증장(공사 중) |
| 공장 현황판 | 장착 엔진, 벤치 순위, 정비 작업장 10곳의 검사 램프 |
| 데이터세트 | 셀 1,000개 × 측정값 4개, 불량 약 20%, 훈련 600 · 검증 200 · 시험 200(2편까지 봉인) |
| 엔진 창고 | 머신러닝 도감 7종(로지스틱 회귀·결정 트리·랜덤 포레스트·그래디언트 부스팅·SVM·나이브 베이즈·k-최근접 이웃) + 신경망 도감 2종(DFF·오토인코더), CNN·LSTM은 보관 |
| 장착·시운전 | 엔진마다 손잡이 하나, 판정 경계 지도, 혼동 행렬 |
| 벤치 | 9종 같은 조건 비교(검증 F1 · 훈련 F1 · 저장 값) |
| 정비 ①~⑩ | 카드 01~10 = 부품 창고 · 뉴런 조립대 · 설계도실 · 계량실 · 첫 시동 · 원인 추적실 · 조정대 · 길들이기 라인 · 개조 공정 · 출고 검사실 |
| 대결 | 로지스틱 회귀(5개) vs DFF(49개), 훈련·검증을 10번 나눠 평균 F1과 이긴 횟수로 판정 → **R 주판봇 승** |
| 출고 | 엔진 선정, 2편 예고 |
| 지식 색인 · 꾸러미 | `#kg`, `#export` (노드 99 · 관계 150 · 문헌 17) |

기본 설정 벤치(시드 고정, `node code/check_numbers.js`로 재현) — 검증 F1: DFF 0.894 · SVM 0.828 · k-최근접 0.784 · 로지스틱 0.782 · 부스팅 0.771 · 랜덤 포레스트 0.711 · 나이브 베이즈 0.667 · 결정 트리 0.636 · 오토인코더 0.581.

엔진 9종은 외부 라이브러리 없이 이 저장소(`build/engines.js`)에서 직접 구현한 단순판입니다. 예컨대 부스팅은 XGBoost 자체가 아니라 같은 원리의 작은 구현입니다.

## 자매편: 배터리 수명 예측 장치 ① 엔진부 (`regression.html`)

같은 셀 1,000개로 **수명(충·방전 횟수)**을 맞히는 예측 장치를 만듭니다. 섹션 순서는 판정기 편과 같고, 두 페이지는 서로 링크됩니다.

| 섹션 | 회귀 편에서 바뀐 점 |
|---|---|
| 데이터세트 | 수명 평균 1,078회 · 표준편차 92회(훈련), 수명도 표준화해 배우고 성적은 회로 되돌려 잼 |
| 엔진 창고 | 머신러닝 도감 8종(선형 회귀·릿지·라쏘·회귀 트리·랜덤 포레스트·그래디언트 부스팅·k-최근접 이웃·가우시안 프로세스) + DFF(출력 항등) |
| 장착·시운전 | 예측 지형 지도, 실제–예측 그림, 허용 오차 슬라이더와 과대예측(길게 틀린 셀) 개수 |
| 벤치 | 검증 평균 오차(MAE, 낮을수록 좋음) · R² · 5번 나눈 평균 ± 편차 |
| 정비 ①②⑤⑧⑨⑩ | ① 출력 부호 검사(카드 01 값은 4칸 모두 틀림) · ② 카드 02의 z = −1.8은 수명 점수로는 맞음 · ⑤ 제곱 손실과 평균 기준선 · ⑧ 손실 + 검증 MAE + 실제–예측 · ⑨ 공장 B 60셀 미세조정 · ⑩ 용량 실험(MAE) |
| 대결 | 릿지(5개) vs 그래디언트 부스팅(100그루), 정답 셀 40개·600개 × 10번 나누기 → **C 조건부** (40개: 릿지 41.3 vs 47.2회, 부스팅 0/10 · 600개: 38.0 vs 29.0회, 부스팅 10/10) |
| 장착 (감사 반영) | 비대칭 비용 슬라이더(과대 1회 = 과소 k회)와 최소 비용 여유분, 가우시안 프로세스 95% 예측 구간 |
| 잡음 바닥 | 수명 공식 잡음(표준편차 30회) → 평균 오차 바닥 ≈ 23.9회, 데이터세트·벤치에 표시 |
| 지식 색인 · 꾸러미 | 노드 103 · 관계 161 · 문헌 19 (`build/kg_reg.json`·`refs_reg.json`·`meta_reg.json`) |

5번 나눈 평균 검증 오차(회): DFF 26.1±0.9 · 가우시안 프로세스 27.0±1.8 · 부스팅 28.8±1.8 · 랜덤 포레스트 33.0±1.6 · k-최근접 33.8±1.7 · 선형 38.0±1.6 · 릿지 38.2±1.7 · 라쏘 38.7±1.9 · 회귀 트리 48.0±3.1. 1·2위 차이(0.9회)는 흔들림보다 작아 "비슷하게 좋다"로 읽습니다. 정비 수치: ⑧ 검증 MAE 23.2회(에포크 90) · ⑨ 그대로 157.1 / 처음부터 42.7 / 전체 27.8 / 어댑터 25.9회 · ⑩ 시드 3개 평균 검증 MAE 최저는 은닉 2개(31.4회, 2위 은닉 4개 32.7회와 차이는 흔들림 안), 은닉 32개는 훈련 10.0 / 검증 39.3회.

## ④ 태양광 패널 셀 생산 공장 (`solar.html`)

6시그마를 목표로 하는 태양광 셀 공장. 원재료 수입처(가상 공급사 A·B·C)·공장(1·2)·생산 방식(2·3교대)·생산 시기(계절)·생산량(가동률 70·85·100%)에 따라 셀 효율 분포가 달라지고, 그래서 불량 판정 문턱도 달라져야 함을 보여 줍니다.

- 품질 특성: 광열화(LID) 뒤 효율 ≥ 22.40% (설명용 규격). 출하 검사는 광열화 전 효율과 EL 크랙만 잼
- 분포: 효율 정규(시간대 24개 혼합), 크랙 포아송, 표본 불량 이항, 작은 표본 평균 t — [확률분포 딕셔너리](https://adminmrobo.github.io/probability_distribution_dictionary/) 링크
- AI 간이 판정기(HTML): v1 = 기준 조건(A·2공장·3교대·봄·85%) 광열화 시험 500개로 학습한 회귀 + 문턱 22.75%, v2 = 조건 인식(부분 풀링)
- 주요 수치: 기준 조건 공정 5.94σ, 최악 조건(C·1공장·2교대·여름·100%) 3.21σ, v1을 그대로 쓸 때 최악 유출 약 4.3만 DPMO
- 대결(여름 분기 18칸): 라벨 60개 → 무승부(26.8억 vs 27.0억, 부분 풀링 24.7억), 600개 → 조건별 승(11.7억 vs 26.2억) → C 조건부
- 다시 만들기: `python3 build/kg_solar.py && node build/build.js` (계산 모듈 `build/solar_sim.js`)

## ⑤ 배터리 열폭주 실험 랩 (`blast.html`) — 증설

소방 당국의 압착 실험 뉴스 사례(MBC, 2026-11-16: 1,300 kg으로 누르자 충전율 100%만 화염, 70%는 연기, 50·30%는 변화 없음)를 출발점으로 삼은 3D 방폭 실험 랩. 뉴스 문장은 옮기지 않고 실험 조건·결과만 사례로 씁니다.

- 3D 랩 12칸(시료 보관 → 압착 프레스 → 방폭 챔버 → 열화상·연기 감지 → 판정실), 압착하면 결과 단계(없음·연기·화염)와 온도 곡선이 나옴
- 모델: 비례 오즈 로지스틱(없음<연기<화염). 입력 = 충전율, 압력(650·1,300·2,000 kg), 형태(원통·각형), 주변 온도. 참 모형은 뉴스 방향에 맞춘 **가정**(80% 화염 약 24%)

- 대결: 주판봇(뉴스 4점, 규제 없음) vs 초파리(실험 60회 + 약한 규제), 새 실험 300회 로그 손실 0.81 vs 0.44 → F
